## Lumtub 0.2.4

### Performance
- **One network layer in the Rust core.** API calls, thumbnails, translations, component and app updates now go through one pooled Rust client (reqwest + tokio): connections are reused across requests, HTTP/2 where the server offers it, gzip/brotli bodies, the system's TLS (Windows certificate store, macOS Keychain, OpenSSL on Linux), and the proxy setting applied directly, SOCKS included, with names looked up by the proxy. Bodies stream back in pieces without blocking the UI. Without the core, dart:io is used as before.
- **One size for the video picture.** Two parts of the player used to set the size libmpv draws at, each its own way, so the picture was rebuilt twice on every resize and every new video. Now one place sets it, fitting the player or, when the picture is zoomed or stretched, covering it.
- **Faster start.** History, the library, settings and preferences are read together instead of one after another, and the proxy, cache folder and components are prepared at the same time.
- **Less work while playing.** The player controls stop asking for heatmap and storyboard data again for videos that have none (lives), a downloaded video's files are read once per play instead of three times, and a failed resolve caused by 429 no longer starts a second yt-dlp that would meet the same limit.
- **Idle stays idle.** The native relay's log is read only while it serves streams.
- **Player bars follow the clock, not every frame.** The progress bar and time used to be rebuilt for every frame mpv reported (60 times a second at 60 fps), even with the bars hidden. Now the bar updates only while it is on screen and the time once a second.
- **Cheaper redraws.** The dark watch page builds its colour scheme once instead of on every redraw, and the block lists are kept as sets and lowercased once, instead of for every video of every list on every redraw; channel block tests on the search page are remembered.
- **No guesswork during playback.** Resting the pointer on a card no longer starts a yt-dlp run while a video plays, so it does not take CPU from the playback.
- **Quicker start without Deno.** When installing Deno failed, the next launches within six hours start without waiting on it again; Settings › tools can still install it.
- **The display may sleep when minimised.** Lumtub keeps the screen on while a video plays, but no longer while its window is minimised.
- **Fewer repeat requests.** A thumbnail that failed is not asked for again for a while when its card scrolls back into view (ten minutes when refused, half a minute when the network failed), and a DeArrow card's fallback YouTube thumbnail is now cached too. Channel feeds read a few minutes ago are reused by the home feed, SponsorBlock segments are asked once per video per session, and the language of a title is worked out once.
- **No two-minute wait on a bad network.** When resolving a video failed on a network error after its retry, the watch page no longer starts a third yt-dlp for the details.
- **Lighter lists.** The narrow and theatre watch pages build comments as they scroll into view, lists that hide watched videos are filtered again only when a video becomes watched, cards rebuild for DeArrow only when their own title or thumbnail changed, and the mini player's hidden controls no longer follow playback.
- **Steadier proxy streaming.** The SOCKS bridge copies in 64 KiB steps instead of 8 KiB, turns off Nagle's delay and resolves the proxy once; the stream relay reuses its buffer and gives up on a reply that stops sending for two minutes instead of waiting forever.

- **The UI no longer spins while waiting for video frames.** Flutter's drawing thread used to poll the GPU in a loop until each video frame was copied; it now sleeps on a D3D11 fence until the copy is done (polling stays as the fallback on drivers without fences). The renderer also no longer allocates a depth and stencil buffer libmpv never uses. Every few minutes of playback the log records the frame timings and the wait, smooth or not.
- **Back to a zone without searching again.** The last four Explore zones (with their mode and filters) are kept for fifteen minutes, so switching back shows the same list at once; 全部 still brings new videos each visit.
- **Less copying of large pages.** Search, channel, related-video, comment and post pages (often 1–2 MB) go to the native core as the bytes that arrived instead of being decoded and encoded again, and the core reads a `/next` page in one pass instead of four. Ranking splits each title into words once instead of twice.
- **Fewer GitHub requests.** A component update check that failed, or that still has to replace the single-file yt-dlp, is retried after an hour instead of at every launch.
- **No pause between stream chunks.** The relay asks for the next 9 MB of a video while the current one is still arriving, instead of after it, so playback no longer waits a round trip every chunk.
- **YouTube playlists open faster.** A playlist is read from YouTube's web API a page at a time, like search and channel pages, instead of starting yt-dlp; yt-dlp stays the fallback.
- **The thumbnail size setting now shows.** Cards decoded thumbnails at most 480 pixels wide whatever size was chosen, so 较高 and 最高 downloaded larger files for no sharper picture. Cards now decode up to the chosen file's width.
- **A refused stream fails fast instead of after 20 seconds.** When YouTube refused a video's address (403) through the stream relay, libmpv saw a reply that kept breaking off, retried, and the video sat on a spinner for 20 seconds before Lumtub reconnected. The relay now asks YouTube before answering and passes the refusal on, so Lumtub gets a fresh address right away. The log also says how old a refused address was and which YouTube client it came from.
- **Translated subtitles load again.** When YouTube refused a translated track and Lumtub translated the original itself, automatic captions failed on their empty in-between cues ("Bad state: No element"), so neither the subtitles nor the bilingual line showed.
### Encrypted DNS
- **Settings › Network › Encrypted DNS** (off by default): on a direct connection, host names for the app's requests and the video relay are looked up over DNS-over-HTTPS with Cloudflare, Google, Quad9 or a custom server, cached for their TTL. If the server can't be reached the system DNS answers, so the app never goes offline over it; choosing a server tests it at once. Through a proxy, the proxy looks names up as before.

### Subtitles and translation
- **A new subtitle panel.** The subtitle button opens a side panel with the first subtitle on the left and the second (shown above it) on the right. A choice applies at once and the panel stays open; tracks are grouped into the video's own, automatic and YouTube auto-translate, with a search for videos with many languages.
- **First and second subtitle languages.** Settings › Subtitles has a first and a second subtitle language. With a second language set, a video opens with that subtitle above the first: the video's own track in that language if it has one, else YouTube's translation. It is not added when the first subtitle is already in that language.
- **Each subtitle has its own font, size, color and opacity**, with a live preview and a nicer default: Microsoft YaHei, a white first line and a smaller light gold second line. "Restore default style" brings it back. While mpv draws subtitles (libass), the second one follows the first one's style.
- **Translation services.** Settings › Translation service picks Google Translate (default, free), DeepL, Microsoft Translator, LibreTranslate or an AI model through any OpenAI-compatible endpoint, with presets for OpenAI, DeepSeek, Anthropic Claude, Google Gemini, Qwen, OpenRouter and Ollama, and prompt presets (line for line, natural, faithful) or your own prompt. Subtitles can be translated with the chosen service instead of YouTube. API keys are encrypted by Windows and kept apart from the settings file; text is only sent when you translate something.
- **The player's More menu is a side panel.** Choices such as quality, zoom, audio quality, play order, sleep timer and playback strategy are chips that apply at once while the panel stays open, instead of a list where each row closed the menu and opened another dialog. Rows are grouped into picture, sound, playback and tools.
- **Tidier player bars.** The top bar keeps back, home, the title (with the channel in fullscreen), cast, picture-in-picture and More; pin on top, audio only, SponsorBlock, playback info, mirror and the in-app mini player became tiles at the top of More, and a small icon in the top bar shows pin and audio only while they are on. Volume moved next to play, and the picture fit moved into More. Buttons light up under the mouse, and the speed, quality and chapter menus open above their button with a check on the current choice, instead of over it.
- **Theme presets.** Settings › Appearance › App theme starts with nine ready-made themes (Classic red, Bay blue, Forest green, Celadon, Lavender, Sakura, Sunset, Graphite and OLED black), each drawn in its light and dark version; one tap sets the colour and palette style, and Theme mode picks light or dark.
- **Tidier filters and menus.** Filter chips and drop-downs in Explore and search are pill-shaped with a hairline outline and a filled look when active; drop-down menus, tooltips and segmented buttons share one rounded style, and navigation labels always use the app font. The home page's welcome banner shows only until there is something to recommend.
- **Subtitles in your language first.** The first subtitle follows the first subtitle language (Windows' language by default, now including Japanese, Korean, German, French and the others listed), and YouTube translates it when the video has none in that language. The second subtitle can be set to the video's own language (uploaded or auto-generated). The subtitle panel offers a translation only when the video lacks your language.
- **Translations follow your language and show side by side.** Translate (comments, descriptions, posts, titles) now translates into Windows' language unless Settings › Translation picks another, and shows the translation under the original, like immersive translation tools; turn off Bilingual to have it replace the original.
- **More translation options, after KISS Translator.** New services: Microsoft Translator works without a key (Edge's free endpoint), DeepLX, Baidu Translate, and Zhipu GLM and SiliconFlow presets for AI. AI translation gains a style (casual, formal, literal, idiomatic and more), a glossary, temperature, a model list fetched from the endpoint, and earlier subtitle lines as context. Translations can look like a quote bar, highlight, dashed underline, dashed box or a blur that clears on hover, above or below the original; text already in the target language is skipped; translations are cached on this computer for 7 days.
- **Subtitle list and line-by-line keys, after Language Reactor.** More settings › Subtitle list (also in the subtitle panel) lists every line of the main subtitle with its time; the line being spoken is marked and kept in view, a click jumps there, and lines can be searched and copied. A / D jump to the previous or next line, R replays the current one, Ctrl+C copies the subtitle on screen. Subtitle parsing and the same-language check now run in the Rust core.
- **Download the cover or subtitles.** The download dialog can now save just the video's largest cover image, or one of its subtitles (including YouTube's translation into your language) as SRT or WebVTT, next to your downloads.

## Lumtub 0.2.4（中文）

- **统一网络层改由 Rust 核心负责**：接口请求、缩略图、翻译、组件和应用更新都走同一个 Rust 连接池（reqwest + tokio）：连接在请求间复用，服务器支持时用 HTTP/2，支持 gzip/brotli 压缩，使用系统自带的 TLS（Windows 证书库、macOS 钥匙串、Linux 的 OpenSSL），代理设置直接生效，SOCKS 也不再绕本地转换，域名由代理解析。响应分块传回，不卡界面。缺少核心时照旧使用 dart:io。
- **视频画面尺寸只在一处设置**：以前播放器有两处各自设置 libmpv 的绘制尺寸，每次调整窗口和换视频都会重建两次画面。现在统一在一处：普通模式按播放器大小适配，缩放或拉伸模式按铺满计算。
- **启动更快**：历史、收藏库、设置和偏好同时读取，不再一个接一个；代理、缓存目录和组件也同时准备。
- **播放时更省**：没有热度图和预览图的视频（如直播）不再反复请求这些数据；本地下载的视频每次播放只读一次文件（以前三次）；因 429 失败时不再额外启动一个注定同样失败的 yt-dlp。
- **空闲时真正空闲**：原生中转只在传输视频流时读取日志。
- **播放时不再猜测预加载**：视频播放时，鼠标停在卡片上不再启动 yt-dlp 预解析，不和播放抢 CPU。
- **缺少 Deno 时启动更快**：Deno 安装失败后，六小时内的启动不再等待重试；仍可在工具更新里手动安装。
- **最小化时允许熄屏**：播放时仍保持屏幕常亮，但窗口最小化后不再阻止熄屏。
- **播放条不再每帧重建**：以前进度条和时间随 mpv 每一帧的位置更新重建（60fps 视频每秒 60 次），控制条隐藏时也一样。现在进度条只在显示时更新，时间每秒更新一次。
- **重绘更省**：深色播放页的配色只计算一次；屏蔽列表改为集合并只转小写一次，不再对每个列表的每个视频每次重绘都重新处理；搜索页的频道屏蔽判断会记住结果。
- **减少重复请求**：加载失败的缩略图在卡片滚回来时暂不重试（被拒绝等十分钟，网络失败等半分钟）；DeArrow 卡片退回的 YouTube 缩略图也会缓存。几分钟内读过的频道订阅源，首页推荐直接复用；SponsorBlock 片段每个视频每次启动只请求一次；标题语言只判断一次。
- **网络差时不再等两分多钟**：解析视频因网络错误重试后仍失败时，播放页不再启动第三个 yt-dlp 去取详情。
- **列表更轻**：窄屏和影院模式的评论滚动到才构建；隐藏已看过的列表只在有视频变为已看完时重新过滤；卡片只在自己的 DeArrow 标题或缩略图变化时重建；小窗隐藏的控制条不再跟随播放刷新。
- **代理下播放更稳**：SOCKS 桥接改为每次 64 KiB（以前 8 KiB）、关闭 Nagle 延迟、代理地址只解析一次；视频中转复用缓冲区，上游两分钟不发数据就放弃，不再无限等待。
- **等待视频帧时界面线程不再空转**：以前 Flutter 绘制线程会循环查询 GPU，直到每一帧复制完成；现在用 D3D11 fence 休眠等待（不支持 fence 的驱动仍用旧方式）。渲染也不再分配 libmpv 用不到的深度/模板缓冲。播放时每隔几分钟把帧耗时和等待情况写入日志，无论是否卡顿。
- **切回分区不再重新搜索**：探索页最近四个分区（连同模式和筛选）保留十五分钟，切回来立即显示同一列表；“全部”每次仍会换新视频。
- **大页面少拷贝**：搜索、频道、相关视频、评论和帖子页面（常有 1–2 MB）直接把收到的字节交给原生核心，不再先解码再编码；`/next` 页面一次遍历读完（以前四次）；推荐排序时每个标题只分词一次。
- **减少 GitHub 请求**：组件更新检查失败，或仍需替换单文件版 yt-dlp 时，一小时后再试，不再每次启动都请求。
- **视频分段之间不再停顿**：中转在当前 9 MB 还在下载时就请求下一段，不再等它下完，播放不用每段都等一次往返。
- **YouTube 播放列表打开更快**：播放列表像搜索和频道页一样走网页接口分页读取，不再启动 yt-dlp；yt-dlp 仍作为后备。
- **缩略图清晰度设置终于生效**：以前无论选什么尺寸，卡片最多按 480 像素宽解码，选“较高”“最高”只是多下载了更大的文件，画面并不更清楚。现在按所选尺寸解码。
- **视频地址被拒时立即重试，不再干等 20 秒**：以前 YouTube 通过中转拒绝视频地址（403）时，libmpv 只看到连接反复中断，转圈 20 秒后才重新连接。现在中转先向 YouTube 请求再回应，把拒绝直接转告，Lumtub 立即换新地址。日志也会记下被拒地址的生成时间和来源客户端。
- **翻译字幕恢复正常**：YouTube 拒绝翻译字幕、改由 Lumtub 自己翻译时，自动生成字幕里的空白过渡段会导致出错（“Bad state: No element”），字幕和双语字幕都显示不出来。

### 加密 DNS
- **设置 › 网络 › 加密 DNS**（默认关闭）：直连时，应用请求和视频中转用 DNS-over-HTTPS 查找网址，可选 Cloudflare、Google、Quad9 或自定义服务器，结果按 TTL 缓存。服务器连不上时自动改用系统 DNS，不会因此断网；选好后会立即测试一次。开着代理时仍由代理解析。

### 字幕和翻译
- **新的字幕面板**：点字幕按钮打开侧边面板，左边选第一字幕，右边选显示在上方的第二字幕。选了立刻生效，面板不关；字幕按视频自带、自动生成、YouTube 自动翻译分组，语言多时可以搜索。
- **第一、第二字幕语言**：设置 › 字幕设置 里可以设第一字幕语言和第二字幕语言。设了第二字幕语言后，打开视频会自动在上方显示这种语言的字幕：视频自带的优先，没有就用 YouTube 自动翻译；第一字幕已经是这种语言时不加。
- **两种字幕分别设置字体、大小、颜色、不透明度**，带实时预览，默认样式也换成更好看的：微软雅黑，第一字幕白色，第二字幕小一号的浅金色，可一键恢复默认。由 mpv 绘制字幕（libass）时，第二字幕跟随第一字幕的样式。
- **翻译服务可选**：设置 › 翻译服务 可选 Google 翻译（默认，免费）、DeepL、微软翻译、LibreTranslate，或任何 OpenAI 兼容接口的 AI 大模型，预置 OpenAI、DeepSeek、Anthropic Claude、Google Gemini、通义千问、OpenRouter、Ollama，提示词有逐行对应、自然口语、忠实直译三种预置，也可以自己写。字幕也可以改用所选服务翻译。API 密钥用 Windows 加密单独保存，不写进设置文件；只有翻译时才发送文字。
- **播放器的“更多设置”改成侧边面板**：画质、画面缩放、音质、播放顺序、定时关闭、播放策略等直接点选项就生效，面板不关；以前每一项都要先关掉菜单再弹出一个对话框。各项按画面、声音、播放、工具分组。
- **播放器上下栏更清爽**：顶栏只留返回、主页、标题（全屏时加频道名）、投屏、画中画和更多设置；窗口置顶、听视频、空降助手、播放信息、镜像翻转、应用内小窗变成“更多设置”顶部的开关块，置顶和听视频开着时顶栏有小图标提示。音量移到播放键旁边，画面比例移进“更多设置”。按钮在鼠标下会高亮，倍速、画质、章节菜单在按钮上方弹出并勾出当前选项，不再盖住按钮。
- **主题预设**：设置 › 外观 › 应用主题 顶部新增九套主题（经典红、海湾蓝、森林绿、青瓷、薰衣草、樱花、日落、石墨、OLED 纯黑），每套同时显示浅色和深色效果，点一下同时换好颜色和调色板风格，明暗跟随“主题模式”。
- **筛选和菜单更整齐**：探索和搜索的筛选项改成胶囊形，未选时细描边、选中时填充；下拉菜单、提示气泡和分段按钮统一成圆角样式，左侧导航文字始终用应用字体。首页的欢迎横幅只在还没有推荐内容时显示。
- **字幕优先显示你的语言**：第一字幕按“第一字幕语言”显示（默认跟随 Windows 语言，现在也认日语、韩语、德语、法语等），视频没有这种语言时用 YouTube 翻译；第二字幕新增“视频原字幕（自带或自动生成）”。字幕面板只在视频没有你的语言时才显示翻译选项。
- **翻译默认译成系统语言，并双语对照**：评论、简介、动态和标题的“翻译”默认译成 Windows 的语言，除非在设置里另选；译文显示在原文下方（像沉浸式翻译），关掉“双语对照”则译文替换原文。
- **翻译设置参考 KISS Translator 扩充**：新增免密钥的微软翻译（Edge 免费接口）、DeepLX、百度翻译，AI 预设加入智谱 GLM 和硅基流动；AI 翻译可选翻译风格（口语、正式、直译、意译等）、术语表、温度、从接口拉取模型列表，翻字幕时带上前几句做上下文。译文样式可选引用竖线、背景高亮、虚线下划线、虚线框、模糊（悬停显示），可放在原文上方或下方；已是目标语言的内容自动跳过；翻过的内容在本机缓存 7 天。
- **字幕列表和按句跳转（参考 Language Reactor）**：更多设置 › 字幕列表（字幕面板右上角也能打开）列出整条字幕和时间，正在说的那句高亮并自动滚到可见处，点一句就跳过去，可以搜索和复制；A / D 跳到上一句或下一句，R 重听这一句，Ctrl+C 复制屏幕上的字幕。字幕解析和同语言判断改由 Rust 核心完成。
- **下载封面和字幕**：下载对话框新增“下载封面”（保存最大尺寸的封面图）和“下载字幕”（可选视频自带、自动生成或翻译成你的语言的字幕，保存为 SRT 或 WebVTT），文件保存在下载文件夹。
