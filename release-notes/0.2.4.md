## Lumtub 0.2.4

### Performance
- **One size for the video picture.** Two parts of the player used to set the size libmpv draws at, each its own way, so the picture was rebuilt twice on every resize and every new video. Now one place sets it, fitting the player or, when the picture is zoomed or stretched, covering it.
- **Faster start.** History, the library, settings and preferences are read together instead of one after another, and the proxy, cache folder and components are prepared at the same time.
- **Less work while playing.** The player controls stop asking for heatmap and storyboard data again for videos that have none (lives), a downloaded video's files are read once per play instead of three times, and a failed resolve caused by 429 no longer starts a second yt-dlp that would meet the same limit.
- **Idle stays idle.** The native relay's log is read only while it serves streams.

| `x64` | Older x64 CPUs |

## Lumtub 0.2.4（中文）

- **视频画面尺寸只在一处设置**：以前播放器有两处各自设置 libmpv 的绘制尺寸，每次调整窗口和换视频都会重建两次画面。现在统一在一处：普通模式按播放器大小适配，缩放或拉伸模式按铺满计算。
- **启动更快**：历史、收藏库、设置和偏好同时读取，不再一个接一个；代理、缓存目录和组件也同时准备。
- **播放时更省**：没有热度图和预览图的视频（如直播）不再反复请求这些数据；本地下载的视频每次播放只读一次文件（以前三次）；因 429 失败时不再额外启动一个注定同样失败的 yt-dlp。
- **空闲时真正空闲**：原生中转只在传输视频流时读取日志。
