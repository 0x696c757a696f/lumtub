## Changes

- Translated subtitles no longer fail with "Too many translation requests". Google's free translation refuses a burst of requests from one address for a while; Lumtub now spaces its requests, waits when Google says it is busy (longer each time), asks again, and if Google still refuses, shows YouTube's own translation instead of none (all platforms).
- Microsoft's free translator works again: Microsoft closed the address it signed in with, and Lumtub now uses the one Edge translates pages with today. With Google Translate chosen (the default), comments, descriptions, chapter titles and live chat are translated with Microsoft's free translator first, so subtitles keep Google's allowance for whole-sentence translation; while either refuses or fails, the other takes over at once, and the first is asked again on the next text.
- When every translation service refuses, the message says they are busy and to try again in a minute, instead of "Couldn't load these subtitles"; another translation error shows its own reason.
- Settings › Translation and AI: tapping Model shows the models the AI endpoint lists to pick from, with typing a name as the last choice (and straight away when the endpoint lists none).
- New translation service MyMemory (free, no key, an optional email raises its daily allowance). It is meant for short texts such as comments and titles; with it chosen, subtitles keep Google Translate. With Google chosen, MyMemory is also the last fallback for short texts when both Google and Microsoft refuse.
- Settings › Translation and AI says what kind of service each one is: an official API that needs your own key, an unofficial web interface that may be limited without notice, or an open-source server.
- LibreTranslate asks the server which languages it knows and by which code, so older servers that call Chinese "zh"/"zt" and Filipino "tl" translate again.
- The update check no longer says "YouTube refused the request (403)": the check goes to GitHub, whose API allows 60 requests an hour per address, which a VPN or shared address soon uses up. Lumtub now reads the latest release from github.com's pages instead; the package is still checked against its signature before it installs. Other GitHub errors name GitHub too.
- When a video can't be played, the message shows the line that names the cause, such as YouTube asking to confirm you're not a bot, instead of a warning yt-dlp printed before it.
- When YouTube takes the network for a bot ("Sign in to confirm you're not a bot") and both IPv4 and IPv6 reach YouTube, the video is asked for once more over the other one, which YouTube rates apart; when that gets through, Lumtub keeps to it for 30 minutes.
- New setting, off by default: Settings › Network › Ask again with my account when blocked. With it on and the browser sign-in signed in, a video YouTube refuses as from a bot is asked for once more with your account (at most 20 times an hour, never for previews), and Lumtub says so when it does.
- One sign-in instead of three: the browser sign-in now does everything. With it Lumtub shows your YouTube home feed, watch history, Watch Later, Liked videos and playlists; likes and dislikes videos and comments; writes comments and replies; subscribes and unsubscribes; saves to and creates playlists; copies your subscriptions and playlists into the library (Settings › YouTube account › Sync now); and, if you turn it on, adds what you watch to your YouTube history. It asks as the YouTube website does, so there is no daily limit and no Google Cloud client to set up.
- The Google sign-in stays as an option for people whose browser sign-in does not work; when both are signed in, the browser sign-in is used.
- The TV-code sign-in is gone: everything it did, the browser sign-in now does. Its saved sign-in is deleted from the device when Lumtub 0.2.54 starts; to also take Lumtub off the account, remove it under your Google account's connected apps.
- Windows, macOS and Linux: YouTube's JavaScript challenges are solved by the QuickJS inside Lumtub's own core, as on phones, instead of starting Deno for each video. The player YouTube sends is prepared once and kept, so later videos of the same player are solved at once. Deno stays as the fallback when the core cannot solve one.
- Settings › Clear local data clears more: the sign-ins item now signs out the browser sign-in too, deletes an old TV-code sign-in and forgets paired AirPlay receivers (it used to sign out of Google only); watch history also clears the watch statistics; "Not interested" also deletes the recommendations kept for the next start; the cache also deletes what Lumtub learned about videos and channels (languages, facts, pictures, AI labels); all settings also resets each channel's own playback settings.
- Signing out asks whether to also delete the playlists synced from YouTube (Liked videos among them); off by default, so they stay in the library as before.
