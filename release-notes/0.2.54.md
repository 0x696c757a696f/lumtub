## Changes

- Translated subtitles no longer fail with "Too many translation requests". Google's free translation refuses a burst of requests from one address for a while; Lumtub now spaces its requests, waits when Google says it is busy (longer each time), asks again, and if Google still refuses, shows YouTube's own translation instead of none (all platforms).
- Microsoft's free translator works again: Microsoft closed the address it signed in with, and Lumtub now uses the one Edge translates pages with today. With Google Translate chosen (the default), comments, descriptions, chapter titles and live chat are translated with Microsoft's free translator first, so subtitles keep Google's allowance for whole-sentence translation; while either refuses or fails, the other takes over at once, and the first is asked again on the next text.
- When every translation service refuses, the message says they are busy and to try again in a minute, instead of "Couldn't load these subtitles"; another translation error shows its own reason.
- Settings › Translation and AI: tapping Model shows the models the AI endpoint lists to pick from, with typing a name as the last choice (and straight away when the endpoint lists none).
- New translation service MyMemory (free, no key, an optional email raises its daily allowance). It is meant for short texts such as comments and titles; with it chosen, subtitles keep Google Translate. With Google chosen, MyMemory is also the last fallback for short texts when both Google and Microsoft refuse.
- Settings › Translation and AI says what kind of service each one is: an official API that needs your own key, an unofficial web interface that may be limited without notice, or an open-source server.
- LibreTranslate asks the server which languages it knows and by which code, so older servers that call Chinese "zh"/"zt" and Filipino "tl" translate again.
- The update check no longer says "YouTube refused the request (403)": the check goes to GitHub, whose API allows 60 requests an hour per address, which a VPN or shared address soon uses up. Lumtub now reads the latest release from github.com's pages instead; the package is still checked against its signature before it installs. Other GitHub errors name GitHub too.
- When a video can't be played, the message shows the line that names the cause, such as YouTube asking to confirm you're not a bot, instead of a warning yt-dlp printed before it.
